# Clean Code Expert System

## وصف المشروع

نظام الخبير للكود النظيف هو أداة لتحليل جودة الكود البرمجي، تقوم بتقييم كود JavaScript وفق المبادئ التي حددها روبرت سي. مارتن في كتابه "Clean Code: A Handbook of Agile Software Craftsmanship". يعتمد النظام على محرك استدلال قائم على قواعد، مبني على مكتبة Experta التي تُعدّ تطبيقاً بلغة Python لخوارزمية RETE المعروفة في نظام CLIPS، وذلك للكشف عن مخالفات جودة الكود وتوليد توصيات إعادة الهيكلة مع تحديد أولوياتها.

يُعالج هذا النظام مشكلة الطابع الذاتي في مراجعة الكود، إذ يوفر آلية رسمية وآلية ومتكررة للكشف عن المشكلات البنيوية والأسلوبية الشائعة في مشاريع JavaScript. وبالإضافة إلى الكشف عن المخالفات، يتكامل النظام مع نموذج Google Gemini اللغوي الكبير لإنتاج نسخ معاد هيكلتها بشكل ذكي من الكود المُحلَّل. كما يتم احتساب درجة Clean Code Score (بين 0 و100) لكل عملية تحليل لتوفير مقياس موحد وقابل للمقارنة لجودة الكود الإجمالية.

يُتيح المشروع وظائفه عبر واجهتين: تطبيق ويب مبني على Flask مخصص للاستخدام المحلي أو للنشر السحابي، وإضافة لمحرر Visual Studio Code تتصل بـ API المنشورة على السحابة لتحليل الملف النشط مباشرة داخل بيئة التطوير.

## الميزات الرئيسية

- **محرك نظام خبير قائم على القواعد**: يستخدم محرك الاستدلال RETE من مكتبة Experta لمطابقة الحقائق المستخرجة من Abstract Syntax Tree مع مجموعة القواعد المعرّفة رسمياً، وتطلق كل قاعدة عند اكتشاف مخالفة Clean Code محددة.
- **تحليل AST لكود JavaScript**: يُحوّل كود JavaScript المصدر (بما في ذلك ES2015 وما بعده) إلى AST هيكلية باستخدام مكتبة esprima، وهي البنية الأساسية التي تُستخرج منها جميع الحقائق.
- **خط أنابيب استخراج الحقائق (Fact Extraction Pipeline)**: يجتاز FactExtractor شجرة AST بشكل تعاودي ويستخرج حقائق مُصنَّفة تشمل: تعريفات الدوال، وتصريحات المتغيرات، وتعبيرات استدعاء الدوال، والثوابت العددية، وشروط جمل if، والمخاوف (المسؤوليات) المكتشفة داخل الدوال.
- **تسع قواعد للكشف عن المخالفات**: يكتشف النظام المخالفات التالية:
  - Long Method: الدوال التي تتجاوز 20 سطراً.
  - Too Many Parameters: الدوال التي تأخذ أكثر من 4 معاملات.
  - Short Variable Name: أسماء المتغيرات غير الوصفية التي يقل طولها عن 3 أحرف.
  - Dead Code (Project-Wide): الدوال المُعرَّفة بأسماء والتي لم تُستدعَ قط ضمن النطاق المُحلَّل.
  - Data Clumps: دالتان أو أكثر تتشاركان قائمة معاملات متطابقة تتكون من 3 عناصر أو أكثر.
  - High Cyclomatic Complexity: الدوال التي يتجاوز تعقيدها الدوراني (Cyclomatic Complexity) القيمة 10.
  - Deep Nesting (Arrow Anti-Pattern): الدوال التي يتجاوز عمق التشعب فيها 3 مستويات.
  - Multiple Responsibilities: الدوال التي تتولى 3 مخاوف وظيفية مختلفة أو أكثر في آنٍ واحد.
  - Magic Number: ثوابت عددية مجهولة المعنى غير 0 و1 و-1.
- **درجة Clean Code Score**: تحتسب درجة جودة موحدة بين 0 و100 باستخدام نظام عقوبات مرجّحة وصيغة Exponential Decay، مع مراعاة كثافة المخالفات نسبةً إلى حجم الكود.
- **إعادة هيكلة بالذكاء الاصطناعي عبر Google Gemini**: يُرسل النظام الكود الأصلي وقائمة المخالفات المكتشفة إلى Gemini API التي تُعيد نسخة مُعاد هيكلتها من الكود وفق مبادئ Clean Code. يعود النظام تلقائياً إلى قالب جاهز إذا كان الـ API غير متاح.
- **سير عمل إعادة التحليل (Re-Analysis Workflow)**: بعد إعادة الهيكلة بالذكاء الاصطناعي، يمكن للنظام إعادة تحليل الكود المُعاد هيكلته عبر نفس خط الأنابيب لإنتاج مقارنة بين الدرجة قبل وبعد التحسين.
- **تصوير شجرة AST**: يُنتج تمثيلاً هرمياً مبسطاً بصيغة JSON لشجرة البرنامج لعرضها في واجهة الويب.
- **بيانات Radar Chart**: يُولّد مجموعة بيانات مخطط رادار بخمسة محاور (Naming, Parameters, Nesting, SRP, Complexity) بمقياس موحد من 0 إلى 100.
- **توليد تقارير نصية**: يُنتج تقرير تحليل قابل للتنزيل بصيغة نص عادي يحتوي على الدرجة وجميع المخالفات مع استراتيجياتها والكود الأصلي والكود المُعاد هيكلته.
- **إضافة VS Code**: إضافة لمحرر Visual Studio Code ترسل محتوى الملف المفتوح إلى الـ API، وتعرض التشخيصات في لوحة Problems، وتفتح لوحة تحكم تفاعلية webview تعرض الدرجة والرسوم البيانية والكود المُعاد هيكلته مع إمكانية تطبيق الكود النظيف مباشرة بنقرة واحدة.
- **واجهة الويب (Web Interface)**: تطبيق Flask بصفحتين: صفحة التحليل القياسي لإدخال مسار الملف، ولوحة التحكم المتقدمة AI Dashboard التي تعرض خط الأنابيب الكامل.

## خط أنابيب التحليل

يتبع النظام خط أنابيب صارماً من خمس مراحل لكل طلب تحليل:

1. **التحليل (Parse)**: يُمرَّر كود JavaScript المصدر إلى `JavaScriptParser.parse()` التي تستدعي `esprima.parseModule()` لإنتاج قاموس AST مع بيانات موقع الكود المصدري.
2. **استخراج الحقائق (Extract Facts)**: يجتاز `FactExtractor` شجرة AST بشكل تعاودي. لكل نوع عقدة معروف (تعريفات الدوال، تصريحات المتغيرات، تعبيرات الاستدعاء، الثوابت، جمل if)، يُنشئ كائنات Fact مُصنَّفة ويُلحقها بالقائمة. كما يتتبع عمق التشعب ويحتسب التعقيد الدوراني أثناء الاجتياز.
3. **تشغيل الاستدلال (Run Inference)**: يُصرّح `CleanCodeExpertSystem` بجميع الحقائق المستخرجة في ذاكرة العمل RETE ثم يستدعي `run()`. تُطابق خوارزمية RETE الحقائق مع جميع القواعد المُعرَّفة، وتُطلق القواعد التي تتحقق شروطها، فتُلحق كائن `RefactoringRecommendation` لكل تطابق.
4. **الدرجة (Score)**: يجمع `CleanCodeScorer` جميع التوصيات المُطلَقة ويُطبّق الأوزان لكل قاعدة، ثم يُطبّع بكثافة السطور ويُطبّق Exponential Decay للحصول على الدرجة الصحيحة النهائية.
5. **توليد المخرجات (Generate Output)**: يجمع النظام الدرجة وقائمة التوصيات المُسلسَلة وملخص الحقائق المستخرجة وشجرة AST المبسطة وبيانات الرادار والكود المُعاد هيكلته في استجابة JSON واحدة.

## مسارات API

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/` | يُقدِّم صفحة التحليل القياسي |

## التثبيت والإعداد

### المتطلبات المسبقة

- Python 3.9 أو أحدث
- pip

### الخطوات

1. انسخ المستودع وانتقل إلى مجلد المشروع.
2. أنشئ بيئة افتراضية وفعّلها:
   ```
   python -m venv .venv
   .venv\Scripts\activate
   ```
3. ثبّت جميع الاعتمادات المطلوبة:
   ```
   pip install flask flask-cors esprima experta
   ```
4. شغّل خادم Flask للتطوير:
   ```
   python app.py
   ```
5. افتح المتصفح وانتقل إلى `http://127.0.0.1:5000`.

### الاستخدام عبر سطر الأوامر

يمكن تشغيل النظام أيضاً من سطر الأوامر بدون واجهة الويب:

```
python main.py <مسار_ملف_js_أو_المجلد>
```

سيقوم هذا الأمر بفحص جميع ملفات `.js` في المسار المحدد وطباعة تقرير نصي منسّق بجميع المخالفات المكتشفة على الإخراج القياسي.

## استخدام إضافة VS Code

تتصل إضافة VS Code الموجودة في مجلد `vsc-extension/` بالنسخة المنشورة على السحابة عبر العنوان `zainalsh.pythonanywhere.com`.

1. افتح أي ملف JavaScript في VS Code.
2. افتح Command Palette بالضغط على (Ctrl+Shift+P).
3. نفّذ الأمر: `Clean Code: Analyze Current File`.
4. ستُرسل الإضافة محتوى الملف إلى الـ API وتملأ لوحة Problems بالتشخيصات وتفتح webview تعرض نتائج التحليل الكاملة.
5. من لوحة الـ webview يمكن تطبيق الكود المُعاد هيكلته مباشرة على الملف النشط بنقرة واحدة.

## مرجع قواعد Clean Code

| اسم القاعدة | الشرط | الخطورة | الاستراتيجية المقترحة |
|---|---|---|---|
| Long Method | عدد أسطر الدالة > 20 | HIGH | Extract Method |
| Too Many Parameters | عدد المعاملات > 4 | MEDIUM | Introduce Parameter Object |
| Short Variable Name | طول الاسم < 3 باستثناء عدادات الحلقات | LOW | Rename Variable |
| Dead Code (Project-Wide) | دالة مُعرَّفة لم تُستدعَ في النطاق المُحلَّل | MEDIUM | Remove Dead Code |
| Data Clumps | دالتان تتشاركان قائمة معاملات متطابقة من >= 3 عناصر | MEDIUM | Extract Class / Introduce Parameter Object |
| High Cyclomatic Complexity | التعقيد الدوراني > 10 | HIGH | Extract Method |
| Deep Nesting (Arrow Anti-Pattern) | عمق التشعب > 3 | MEDIUM | Extract Method / Guard Clauses |
| Multiple Responsibilities | الدالة تتولى >= 3 مخاوف مختلفة مع تعقيد > 1 | HIGH | Extract Method / Single Responsibility Principle |
| Magic Number | ثابت عددي مجهول المعنى غير 0 و1 و-1 | LOW | Replace with Named Constant |

## خوارزمية الدرجة (Scoring Algorithm)

تُحتسب درجة Clean Code Score وفق الخطوات التالية:

1. تُحصى جميع التوصيات المُطلَقة لكل نوع قاعدة.
2. يُضرب عدد كل قاعدة في وزنها. تستخدم القواعد المتكررة الثانوية (Magic Number, Short Variable Name) مقياس الجذر التربيعي لمنع تراكم العقوبات المفرطة.
3. تُطبَّع العقوبة الإجمالية بكثافة المشكلات: `normalized_penalty = (total_penalty * 100) / total_lines`.
4. يُطبَّق Exponential Decay: `score = 100 * (0.99 ^ normalized_penalty)`.
5. تُقيَّد النتيجة في النطاق [0, 100] وتُقرَّب إلى أقرب عدد صحيح.

درجة 100 تعني عدم اكتشاف أي مخالفة. تضمن دالة Exponential Decay أن عدداً قليلاً من المخالفات في قاعدة كود كبيرة يُفضي إلى درجة مرتفعة، بينما يُدهور التركيز الكثيف للمخالفات الدرجة بشكل متسارع.
